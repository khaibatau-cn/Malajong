# Malajong

**A single-player roguelike deckbuilder played with Hong Kong Mahjong tiles.**

Built by team **SanRokuNana** — CodeCatalyst, Swinburne University.

Draw a hand of tiles, play Mahjong sets to score against an escalating quota, and spend your
winnings on passive artifacts between rounds. Think Balatro's run structure, but the deck is a
Mahjong wall and the combos are Chow, Pong and Kong.

---

## What makes it not just "Balatro with mahjong tiles"

That description is an aesthetic, not a design. The actual hook comes from something a 52-card
deck structurally cannot do.

Mahjong has three fixed suits, and its two core combos have **suit-dependent shapes**: a Chow needs
three sequential tiles *of the same suit*, while a Pong or Kong needs identical tiles regardless of
suit. In a card deck any suit can complete any hand shape — there is no equivalent constraint.

Malajong builds its central decision on that asymmetry:

- **Suit Affinity** — playing combos in a suit raises that suit's multiplier and decays the other
  two. Committing to one suit is the run's defining choice.
- **Honor tiles as a third resource** — Winds and Dragons have no scoring role in real Mahjong, so
  they're repurposed as the consumable/effect layer rather than a bolted-on tarot system.

## How a run plays

You have **5 rounds**, each with a score quota. Miss one and the run is over.

| Round | Quota |
|---|---|
| 1 | 150 |
| 2 | 350 |
| 3 | 800 |
| 4 | 1,800 |
| 5 | 4,000 |

Each round you hold **14 tiles**, with **4 hands** to play and **3 discards** to dig with.

**Scoring** is `Fu × Fan` — Mahjong's own vocabulary for Balatro's chips × mult:

| Combo | Tiles | Fu | Fan |
|---|---|---|---|
| Pair | 2 identical | 10 | ×1.5 |
| Chow | 3 sequential, same suit | 30 | ×3.0 |
| Pong | 3 identical | 40 | ×4.0 |
| Kong | 4 identical | 80 | ×6.0 |
| Concealed Kong | 4 identical, all self-drawn | 100 | ×8.0 |

Whole-hand bonuses stack on top — a Pure Hand (single suit) or All Honors hand multiplies hard.
Clear the quota and you reach the shop, where spirits cost ¥5 each and change how everything above
scores.

### Dead hands

The smallest legal play is a Pair, so a hand with no Pair, Chow, Pong or Kong **cannot be played at
all**. With discards left you dig your way out. With none, you get one appeal to the lucky cat: a
redraw. Find a combo and you survive with an extra discard; find nothing and the run ends.

Full design notes in [`DEAD_HAND_REDRAW.md`](DEAD_HAND_REDRAW.md).

## Running it

Requires **Unity 6** (2D URP). Open the project, then:

1. Open the scene `Assets/Scenes/ILoveCoCa.unity`
2. Run **Malajong → Setup Playable Scene Placeholder** from the menu bar
3. Save the scene (`Ctrl+S`), then press Play

Step 2 matters. The entire UI is **generated by an editor tool**, not hand-built in the scene, so
after pulling changes you rebuild the scene rather than merging someone else's scene file. This is
the single most common reason a change "doesn't show up".

### Editor tools

| Menu item | Does |
|---|---|
| `Malajong → Setup Playable Scene Placeholder` | Rebuilds the whole UI, wires every reference, regenerates the tile prefab |
| `Malajong → Generate All Game Data` | Creates the TileData and SpiritData assets |
| `Malajong → Import UI Skin Sprites` | Applies pixel-art import settings, wires spirit icons by filename |
| `Malajong → Bake Title Sprite` | Knocks out the title art's background layer and trims it |
| `Malajong → Rebuild Pixel Font Asset` | Regenerates the m5x7 TMP font asset |
| `Malajong → Debug → Force Dead Hand` (`Ctrl+Shift+D`) | Deals an unplayable hand in Play mode |

## Project layout

```
Assets/Script/
├── Core/        Tile, TileData, TileBag, PlayerHand, Combo, ScoreEngine, SuitAffinity
├── Roguelike/   GameManager — run state, rounds, turns, economy, loss conditions
├── Artifacts/   SpiritData base + one subclass per spirit
├── UI/          UIManager, TileUI, affinity meters, theme, audio, BalatroFeel/ juice
├── Editor/      Scene generation, asset wiring, sprite baking, debug menu
└── Testing/     Standalone MonoBehaviour harnesses

Assets/ScriptableObjects/
├── Tiles/       34 TileData assets (Bamboo/Characters/Dots 1-9, Honors 1-7)
└── Spirits/     8 SpiritData assets
```

The wall is **136 tiles** — 34 kinds × 4 copies. No flowers or seasons.

### Two conventions worth knowing

**Colour lives in `MalajongTheme`, shape lives in `MalajongSkin`.** No UI script should declare a
raw `new Color(...)`; if a shade is missing, add it to the theme. An earlier build accumulated ~30
near-identical hand-picked navies precisely because there was nowhere central to put them.

**Spirit icons wire by filename.** Drop `MySpirit.png` into `Sprites/UI/Icons/Spirits/` and it
attaches to `MySpirit.asset` automatically — no inspector dragging, no mapping table.

## Current state

**Working:** full turn loop, combo detection and scoring, suit affinity, 8 spirits, shop and
economy, both loss conditions, title screen, animated Balatro-style scoring sequence.

**Not built yet:** the 8-ante structure (currently 5 rounds), Boss Wind constraints, honor-tile
effects (`HonorEffect` exists on `TileData` but nothing resolves it), tenpai scoring.

**Known issues:**
- `ScoreEngine.PreviewScore` calls `spirit.OnComboScored`, which has side effects — `RestlessWind`
  grants a real discard on every tile click, and `BambooVow`'s accumulator ratchets without a play.
- Pure Hand / All Honors bonuses check for a 13-tile hand, but hands hold 14, so they never fire.
- The Fu/Fan values in code, in the design doc, and in the in-game Run Info panel disagree.
- `DiscardsRemaining` has no upper bound.
